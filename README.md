# MOSS SALE — мультиарендная версия

Один экземпляр бота обслуживает много компаний. Клиент ничего не устанавливает:
переходит по ссылке, вводит код — и работает со своим профилем ниши.

Это **этап 1** из ТЗ: база, мультиарендность, активация по ссылке, приглашения,
кеширование промпта, лимиты и учёт расхода. Мастер брифа (этап 2) пока не готов —
профиль ниши назначается скриптом `seed.py`.

---

## Что изменилось по сравнению с прежней версией

| Было | Стало |
|---|---|
| Список разрешённых `ALLOWED_USER_ID` в переменных | Компания пользователя в базе, роли владелец/менеджер |
| Ниша — файл `trainer/niches/moss.json`, одна на бота | Профиль в базе, свой у каждой компании, с версиями |
| Статистика в SQLite, терялась при каждом деплое | PostgreSQL, живёт между деплоями |
| Системный промпт слался целиком на каждом ходе | Помечен для кеширования — вдвое дешевле |
| Диалог вёл Opus | Диалог ведёт Sonnet, разбор делает Opus один раз за сессию |
| Расход неизвестен | Каждый вызов пишется в `usage_log` с ценой в долларах |

Прежняя версия осталась нетронутой в папке `moss_trainer_update` — если что-то
пойдёт не так, можно вернуться к ней.

## Запуск на Railway

**1. Добавить Postgres.** В проекте: `New → Database → PostgreSQL`.
Переменная `DATABASE_URL` появится сама, руками её вписывать не надо.

**2. Переменные окружения:**

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | токен от BotFather |
| `ANTHROPIC_API_KEY` | да | ключ Anthropic |
| `DATABASE_URL` | да | подставляет Railway |
| `ADMIN_IDS` | да | ваш telegram_id — для команд `/newcompany` и `/spend` |
| `OPENAI_API_KEY` | нет | распознавание голоса и озвучка; без него бот работает |
| `TRAINER_MODEL` | нет | модель диалога, по умолчанию `claude-sonnet-5` |
| `DEBRIEF_MODEL` | нет | модель разбора, по умолчанию `claude-opus-5` |

**3. Задеплоить.** Схема базы создаётся при первом старте сама.

**4. Завести первую компанию** — прямо в боте:

```
/newcompany MOSS Алматы | team | client@mail.kz
```

Бот вернёт ссылку активации. Отдаёте её клиенту — дальше он сам.

Либо из консоли, сразу с профилем ниши из заготовки:

```bash
python seed.py "MOSS Алматы" team moss
```

## Как это выглядит для клиента

1. Оплатил → получил ссылку `t.me/ВашБот?start=A7K2ND9P`
2. Перешёл → стал владельцем компании
3. Профиль ниши уже назначен (этап 1) либо заполняет бриф (этап 2)
4. `/invite` → получил ссылку для менеджеров, кинул в рабочий чат
5. Менеджеры перешли → привязались к его компании
6. Тренируются. Владельцу — `/dashboard` со сводкой по отделу

## Команды

**Менеджер:** «🎯 Тренажёр», «📊 Статистика», `/stats`, `/help`

**Владелец компании:** `/dashboard` — сводка по отделу · `/team` — состав и
активность · `/invite` — ссылка для менеджеров · `/revoke` — отозвать ссылку ·
`/limits` — тариф и остаток · `/profile` — профиль ниши · `/export` — выгрузка CSV

**Владелец продукта (только `ADMIN_IDS`):** `/newcompany` — создать компанию ·
`/spend` — расход по всем клиентам за 30 дней

## Проверка себестоимости на живых данных

Расчёт обещает **47 ₸ за тренировку**. Проверить это на реальных вызовах:

```
/spend
```

Команда покажет фактический расход по каждой компании за 30 дней.
Если цифра заметно выше расчётной — первым делом смотреть, попадает ли кеш:

```sql
SELECT kind, SUM(cache_read) AS из_кеша, SUM(input_tokens) AS обычных
FROM usage_log GROUP BY kind;
```

У `step` значение `из_кеша` должно быть в разы больше `обычных`. Если кеш нулевой —
значит, паузы между ходами длиннее пяти минут и запись не доживает; тогда экономия
теряется, и это надо учесть в тарифах.
